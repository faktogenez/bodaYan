# Changelog

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
версии — по [Semantic Versioning](https://semver.org/lang/ru/).

## [1.1.2] - 2026-11-26

### Changed

- **Снята привязка пользовательской сессии к никнейму `bodayan`**: удалён блок-лист стандартного ника из центрального валидатора. Теперь принимается любой никнейм, проходящий технические требования Minecraft (3–16 символов, латиница/цифры/`_`), в том числе `bodayan` в любом регистре. Валидатор, модуль пользовательской сессии, main-процесс и renderer по-прежнему используют единый источник правил, но больше не имеют «зарезервированных» и «запрещённых» имён.
- Дефолтный/предустановленный список никнеймов лаунчера больше не содержит записи `bodayan`.

### Removed

- Константа `STANDARD_USERNAME` и связанная с ней проверка/сообщение об ошибке удалены из `src/nicknameValidation.js`; экспорт `STANDARD_USERNAME` убран из `src/nicknameSession.js`.

### Tests

- Обновлены автотесты (`test-nickname-validation.js`, `test-nickname-session.js`, `test-renderer-auth.js`, `smoke-nickname-live.js`): кейсы отклонения `bodayan` заменены на кейсы приёма. Вход с `bodayan`/`BodaYan`/`BODAYAN` и произвольными никами проходит успешно.
- `npm test` — 51/51 PASS.

## [1.0.21] - 2026-11-22

- Добавлен per-user NSIS-установщик с ярлыками на рабочем столе и в меню «Пуск», а также регистрацией в списке установленных приложений.

### Tests

- Проверена иконка в свежем EXE и реальном окне Windows при 125% DPI (WM_GETICON 40×40 и 20×20).

## [1.0.20] - 2026-11-21

### Added

- **Сохранение никнейма между сессиями**: введённый ник запоминается после успешного входа и автоматически подставляется в поле при следующем запуске. Значение хранится в `localStorage` под ключом `launcher.username`; невалидный сохранённый ник отбрасывается. Legacy-ключи прошлых версий (`appleLauncher.username`, `minecraft_username`) по-прежнему очищаются при старте, чтобы не подставлялся ник, навязанный автозаполнением.

### Fixed

- **Устранено дублирование текста загрузки в нижней строке интерфейса**: пока виден индикатор загрузки (после нажатия «Играть»), нижняя строка статуса скрывается (`visibility: hidden`) и больше не дублирует подпись прогресса; при завершении загрузки/обновления и в состояниях ошибок строка корректно возвращается.

### Changed

- В фазе `ready` обновления лаунчера добавлен сброс индикатора загрузки, чтобы нижняя строка возвращалась во всех итоговых состояниях.

### Tests

- Обновлены автотесты renderer-auth и live-smoke никнейма: проверяются сохранение и автоподстановка ника, скрытие нижней строки во время загрузки и её возврат после завершения.
- CDP-верификация обложки (`verify-launcher-cover.cjs`): добавлены проверки видимости строки статуса в состояниях загрузки/покоя; замеры геометрии карточки сделаны атомарными (устойчивость к фоновым событиям и пересчёту раскладки); прогон принудительно выполняется в dev-режиме.

### Changed

- Прогресс-бар загрузки полностью заменяет блок «Создать аккаунт» по расположению и размерам; все остальные элементы формы сохраняют исходное положение и вертикальные отступы на любых поддерживаемых разрешениях.

### Tests

## [1.0.18] - 2026-11-21

### Removed

### Tests

## [1.0.16] - 2026-11-21

### Added

## [1.0.15] - 2026-11-21

### Fixed

- **Реальная причина остановки самообновления на 77%**: apply-скрипт использовал конвейер `tasklist … | find …`, который в отсоединённом `cmd.exe` (spawn с `detached:true`, `stdio:"ignore"`) **зависает навсегда** — цикл ожидания никогда не завершался, и замена файла не запускалась. Теперь apply-скрипт не использует конвейеры и внешние `tasklist`/`find`: он циклично повторяет встроенную команду `move /Y` (файл разблокируется, как только завершатся процесс лаунчера и portable-обёртка), с ограничением числа попыток, журналом `apply-launcher-update.log` и резервным путём `copy /Y` + `del`.

> Примечание: apply-скрипт генерируется **уже запущенной** версией лаунчера, поэтому исправление затрагивает самообновление от 1.0.15 и выше. Для перехода с более старых версий требуется однократная замена EXE вручную.

## [1.0.14] - 2026-11-21

## [1.0.7] - 2026-11-21

### Changed

- **Постоянный каталог данных**: игровые данные больше не создаются рядом с EXE (в т.ч. на рабочем столе). В сборке `DATA_DIR = %APPDATA%\AppleLauncher`; при первом запуске новой версии старые данные из папки EXE переносятся автоматически. Папка EXE (`EXE_DIR`) используется только для поиска JRE и миграции.
- **Встроенная проверка целостности**: `ensureGameFiles()` сверяет SHA1/размер каждого файла с манифестом и автоматически докачивает отсутствующие/повреждённые — при старте лаунчера, по кнопке и перед запуском игры.
- Модпак переведён на релиз **`modpack-v2`**: в манифест добавлен `versions/Forge 1.16.5/Forge 1.16.5.json` (ранее вызывал ошибку «файл не найден» на чистой системе).

### Added

- `scripts/assetName.js` — каноническое имя ассета (путь → `a__b`), общее для генератора манифеста и публикации.
- `scripts/publish-modpack.js` + npm-скрипты `manifest` и `publish:modpack` — публикация модпака одной командой.

## [1.0.6] - 2026-11-19

### Fixed

- Повторный крэш `spawn cmd.exe ENOENT`, первопричина: текущая версия лаунчера бралась из внешнего `config.json` (`selfUpdate.currentVersion`), который «застревал» на старой версии (1.0.3) — self-update ложно срабатывал при каждом запуске. Теперь версия берётся из самого EXE (`app.getVersion()`).
- Устойчивость запуска apply-скрипта: `cmd.exe` запускается по абсолютному пути (`%ComSpec%`), а дочернему процессу принудительно добавляется `%SystemRoot%\System32` в `PATH` (при урезанном `PATH` не находились ни `cmd.exe`, ни `tasklist/find/ping/move`).

## [1.0.5] - 2026-11-19

### Fixed

- Крэш main-процесса `spawn cmd.exe ENOENT` при автообновлении: путь к `cmd.exe` берётся из `%ComSpec%` (fallback `%SystemRoot%\System32\cmd.exe`), добавлен обработчик `error` дочернего процесса. Ранее при отсутствии `cmd.exe` в `PATH` приложение падало uncaught-исключением.

## [1.0.0] - 2026-11-19

Первый публичный релиз.

### Added

- Portable-сборка одним EXE (`electron-builder`, x64, asar, максимальное сжатие).
- Интерфейс в стиле Apple (glassmorphism) с настраиваемой темой через `config/config.json`.
- Динамическая смена фонового изображения при каждом запуске.
- Запуск Minecraft 1.16.5 + Forge с флагами `--add-opens` (совместимость с Java 17).
- Оффлайн-авторизация (UUID v3 через MD5) — режим «локальный игрок».
- Исправление библиотеки `authlib` (2.1.28 → 2.3.31) для работы сетевой игры.
- Прогресс-бар со стадиями: библиотеки, ассеты, Forge, загрузка файлов.
- Автоподключение к серверу (`quickPlay`) и автоскрытие окна при запуске игры.
- Управление списком серверов: `servers.dat` перезаписывается из конфига (с резервной копией).
- Автообновление игровых файлов по манифесту (SHA1 + размер, докачка через `.part`).
- Самообновление лаунчера через GitHub Releases (подмена EXE внешним `.bat`).
- Модуль поиска Java: `javaPath` → встроенная JRE → `java` из PATH.
