### 1.1. Геометрия сетки (входные параметры, уже в конфиге)

Файл: `C:\Server_Skyblock\plugins\BentoBox\addons\BSkyBlock\config.yml`

| Параметр | Строка | Значение | Смысл |
|---|---|---|---|
| `distance-between-islands` | 54 | **64** | `S` — половина шага сетки |
| `protection-range` | 58 | **24** | `P` — радиус защиты острова |
| `start-x` / `start-z` | 65/67 | **0 / 0** | центр сетки = центр мира |
| `island-height` | 72 | **64** | Y, на который ставится **bedrock** острова |
| `max-islands` | 86 | **12** | лимит островов на игрока/команду |
| `world-name` | 27 | `bskyblock_world` | мир SkyBlock |
| `use-own-generator` | 77 | `false` | генерация BentoBox |

**Шаг центров островов:** `D = 2·S = 128` (подтверждено комментарием `config.yml` стр. 50 и дампом `DefaultNewIslandLocationStrategy.nextGridLocation`).
**Ячейка `(0, 0)` зарезервирована** под спавн — первым игрокам выдаётся **`(0, 128)`**, далее по детерминированной спирали: `(128,128) → (128,0) → (128,-128) → (0,-128) → (-128,-128) → (-128,0) → (-128,128) → (-128,256) → …`

**Радиусы:**
- контент-радиус острова (из габаритов `is.schem`) — `r_i = 23` (`47/2 ≈ 23,5`);
- контент-радиус спавна (из габаритов `spawn_new.schem`) — `r_s = 40` (`80/2 = 40`);
- радиус защиты спавна `P_s = 48` — BSkyBlock выставляет его **автоматически** как `2 × protection-range` в команде `/bsbadmin setspawn` (проверено декомпиляцией `AdminSetspawnCommand`); концепт (раздел 13) рекомендовал 40 — см. п. 4.6.

### 1.2. Проверка отсутствия пересечений (обязательный расчёт)

| Условие | Расчёт | Итог |
|---|---|---|
| остров ↔ остров | `2P = 48 ≤ D = 128` | ✓ зазор `D − 2P = 80` |
| спавн ↔ остров | `P_s + P = 48 + 24 = 72 ≤ D = 128` | ✓ зазор 56 |
| видимость соседа | `S + P = 64 + 24 = 88 ≤ H = 128` (`H = view-distance 8 × 16`) | ✓ запас 40 |
| контент острова в защите | `r_i = 23 ≤ P = 24` | ✓ |
| контент спавна в защите | `r_s = 40 ≤ P_s = 48` | ✓ |

### 1.3. Целевые координаты (утверждаемая таблица)

| Величина | Значение | Обоснование |
|---|---|---|
| Центр спавна (горизонталь) | **X = 0, Z = 0** | центр сетки (`start 0/0`), ячейка зарезервирована |
| Плоскость **bedrock** всех островов | **Y = 64** | `island-height: 64`; «правило одной плоскости» (раздел 13.2) |
| Плоскость **грунта** (ходибельная) островов | **Y = 86** | `64 + (23 − 1) = 86` — bedrock `is.schem` на локальном `y=1`, грунт на `y=23` |
| Точка входа игрока на спавне | **≈ (0.5, 86, 0.5)**, взгляд yaw/pitch задать на этапе 2 | грунт спавна привести к плоскости островов (Y = 86) |
| Границы защиты спавна | `x ∈ [−48, 48]`, `z ∈ [−48, 48]` | `P_s = 48` |
| Границы защиты острова | центр ± 24 | `P = 24` |
| Первый игровой остров | **(0, 128)** | спираль `nextGridLocation` |
| Шаг сетки центров | **128** | `2·S` |

> **Почему грунт на 86, а не на 64:** bedrock — это «якорь» острова (BentoBox ставит его на `island-height = 64`), а сам остров «растёт» вверх на 22 блока (у `is.schem` bedrock на локальном `y=1`, грунт на `y=23`). Поэтому единая плоскость у **bedrock** — 64, а у **грунта** — 86. Спавн должен быть приведён к плоскости грунта 86, иначе он окажется ниже/выше островов на 22 блока.

**Проверка успешности:** стать в центр и проверить блок под ногами и базу острова:

### 2.2. Регистрация острова-спавна и назначение спавна

Порядок обязателен: сначала появиться **на** острове, затем регистрировать/назначать.

```text

/tp 0.5 86 0.5
/bsbadmin register          # создать/привязать остров в зарезервированной ячейке (0,0), пометить reserved
/bsbadmin setspawn          # пометить этот остров как спавн режима (+ защита = 2×P = 48)
```

**Проверка успешности:**
```text
/bsbadmin range display     # должно показать protection range = 48
```
В файле `C:\Server_Skyblock\plugins\BentoBox\database\Island\*.json` у острова спавна должно появиться `"spawn": true`, `"reserved": true`, центр `[bskyblock_world, 0, 64, 0, …]`, `protectionRange: 48`.
В `C:\Server_Skyblock\logs\latest.log` не должно быть новых `ERROR`/`SEVERE`.

**Критерий готовности:** в игре `/bsbadmin range display` на спавне = 48; в БД появилась запись со `spawn: true`.

### 2.3. Точка появления игроков и поворот камеры

```text
# встать в точку появления, повернуться нужным образом
/tp 0.5 86 0.5 0 0          # yaw = 0 (взгляд на +Z — в сторону первого острова (0,128)), pitch = 0
/bsbadmin setspawnpoint     # зафиксировать текущую позицию+поворот как точку появления острова-спавна
/setworldspawn              # ванильный спавн мира bskyblock_world = текущая точка
```

**Поворот камеры (ориентиры):** игрок должен смотреть вдоль «улицы» к первому острову. Направления Minecraft:
- `yaw = 0` → на **+Z** (юг) — **рекомендуется** (первый остров `(0,128)` лежит на +Z);
- `yaw = 180` → на −Z; `yaw = 90` → на −X; `yaw = -90` (270) → на +X;
- `pitch = 0` (горизонт). Доворот задаётся в `/bsbadmin setspawnpoint` текущим направлением взгляда.

- нет «дыр» в основании острова (нижняя граница мира не обрезала конус);
- соседний остров целиком попадает в зону видимости (`S + P = 88 ≤ 128`).

**Критерий готовности:** острова визуально целые, не обрезаны, соседи различимы — переход к этапу 4.

**Критерий готовности:** правила острова соответствуют концепции.

### 4.6. Решение по `P_s` (радиус защиты спавна)

BSkyBlock жёстко ставит `P_s = 2 × protection-range = 48` при `/bsbadmin setspawn`. Концепт рекомендовал 40. Варианты:

- **принять 48** (ничего не делать) — простое и стабильное; **рекомендуется**;
- **переопределить на 40** — после `setspawn` выполнить `/bsbadmin range set 40`, стоя в центре спавна (но следующая команда `setspawn` снова выставит 48).

**Критерий готовности:** значение `P_s` согласовано с заказчиком и зафиксировано в SESSION_HANDOFF.md (этап 5).

```text
/bbox reload                 # перезагрузка BentoBox без рестарта
```

**Проверка успешности:** в `logs\latest.log` нет `ERROR`/`SEVERE`; `Loaded 8 addons.`, `All blueprints loaded.`
**Критерий готовности:** все правки применены, сервер стартует без ошибок.
